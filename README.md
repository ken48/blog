# Личный блог

Сайт: https://ken48.github.io/blog/

## Публикация

Добавляйте и редактируйте заметки в репозитории
[ken48/obsidian-posts](https://github.com/ken48/obsidian-posts):
`2026-09-09 Название заметки.md`. Чтобы опубликовать изменения, откройте
Actions → Build and Deploy в репозитории сайта и нажмите Run workflow.
Сборка скачает актуальные заметки, подготовит посты, соберёт Chirpy и
опубликует сайт. Исходные заметки не изменяются. Пустые файлы и файлы без
даты не публикуются.
Будущие даты Jekyll публикует только при сборке после наступления даты;
для этого можно вручную запустить Build and Deploy в Actions.

Теги необязательны. Чтобы добавить их, поместите в начало заметки:

```yaml
---
tags: [работа, технологии]
---
```

Заголовок и дата берутся из имени файла; их можно переопределить в этом же
блоке. `published: false` исключает заметку из сайта, но файл остаётся
видимым в публичном репозитории. Ссылки на посты сохраняются при изменении
текста, но меняются при переименовании исходного файла.

## Настройки

- `site/_config.yml`: имя, описание, язык и адрес сайта.
- `site/_tabs/about.md`: страница «О сайте».
- `site/_data/contact.yml`: ссылки в боковой панели.
- Комментарии пока выключены; провайдер подключается в `_config.yml`.
- Тема: [Chirpy](https://github.com/cotes2020/jekyll-theme-chirpy),
  основа: [Chirpy Starter](https://github.com/cotes2020/chirpy-starter).

Один раз выберите Settings → Pages → Build and deployment → Source →
GitHub Actions. После объединения PR сайт публикуется автоматически.
Проверки PR собирают сайт без публикации.

## Локальный просмотр (необязательно)

Нужны Ruby 3.4 и Bundler:

```sh
git clone https://github.com/ken48/obsidian-posts.git ../obsidian-posts
ruby tools/prepare-posts.rb ../obsidian-posts
cd site
bundle install
bundle exec jekyll serve
```

Открыть http://127.0.0.1:4000/blog/.

## Статьи из других репозиториев

Раздел «Статьи» собирается из корневых README публичных репозиториев,
перечисленных в `article-sources.json`. Порядок списка задаёт порядок статей.
`repo` — имя репозитория, `slug` — постоянная часть адреса статьи. Пример:

```json
{"repo": "ken48/obsidian-notes", "slug": "notes"}
```

Сборка берёт актуальную основную ветку каждого источника. Заголовок — первый
заголовок первого уровня README; `README.md` и `readme.md` поддерживаются.
HTML-картинки и обычные Markdown-картинки с относительными путями копируются
в сайт. Внешние ссылки остаются прежними. Исходные репозитории не изменяются.
Файлы `lead.md` и другие материалы автоматически не публикуются.

Сгенерированные `site/articles/` и `site/_data/articles.json` не нужно
добавлять в Git. Если источник недоступен или картинка отсутствует, сборка
завершается ошибкой; опубликованная версия сайта остаётся прежней.

Изменение репозитория статьи само по себе не запускает сборку блога.
Чтобы обновить статьи, откройте Actions → Build and Deploy → Run workflow
в репозитории блога. Любой push в `main` блога также обновит все статьи.

Для локального просмотра сначала выполните `python3 tools/prepare-articles.py`
(Python 3.9+ и Git), затем обычную подготовку постов и сборку сайта.

Дата статьи — committer date последнего коммита основной ветки источника,
показанная по московскому времени. Она отображается как обычная дата.
Статьи включены в общий архив вместе с заметками; порядок — по убыванию даты.
Новый коммит и пересборка изменят дату и место статьи в архиве, но не её URL.
