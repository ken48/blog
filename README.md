# Личный блог

Сайт: https://ken48.github.io/blog/

## Публикация

Добавляйте и редактируйте заметки в каталоге `posts/` репозитория
[ken48/publications](https://github.com/ken48/publications). Статьи лежат в
`articles/<article>/`. Каждый публикуемый файл должен содержать заголовок
первого уровня в формате `# Название`. Чтобы опубликовать изменения, откройте
Actions → Build and Deploy в репозитории сайта и нажмите Run workflow.
Сборка скачает источник из `content-sources.yml`, подготовит материалы,
соберёт Chirpy и опубликует сайт. Исходные репозитории не изменяются. Пустые
файлы пропускаются, а неверный формат даты останавливает сборку с указанием
проблемного файла.
Будущие даты Jekyll публикует только при сборке после наступления даты;
для этого можно вручную запустить Build and Deploy в Actions.

Теги необязательны. И в заметках, и в статьях их можно записать отдельной
строкой в начале или конце текста:

```markdown
#работа #технологии
```

При сборке эта строка превращается в метаданные и удаляется из опубликованного
текста. Также поддерживаются теги в YAML front matter:

```yaml
---
tags: [работа, технологии]
---
```

Дата и адрес берутся из имени файла, а заголовок — из строки `# Заголовок`.
При сборке заголовок удаляется из тела, чтобы не дублироваться на странице.
`published: false` исключает заметку из сайта, но файл остаётся
видимым в публичном репозитории. Ссылки на посты сохраняются при изменении
текста и заголовка, но меняются при переименовании исходного файла.

## Настройки

- `site/_config.yml`: имя, описание, язык и адрес сайта.
- `site/_tabs/about.md`: страница «О сайте».
- `site/_data/contact.yml`: ссылки в боковой панели.
- Комментарии пока выключены; провайдер подключается в `_config.yml`.
- Тема: [Chirpy](https://github.com/cotes2020/jekyll-theme-chirpy),
  основа: [Chirpy Starter](https://github.com/cotes2020/chirpy-starter).

Один раз выберите Settings → Pages → Build and deployment → Source →
GitHub Actions. После объединения PR сайт публикуется автоматически.
Проверки PR собирают сайт без публикации.

## Локальный просмотр (необязательно)

Нужны Ruby 3.4 и Bundler:

```sh
ruby tools/prepare-content.rb
cd site
bundle install
bundle exec jekyll serve
```

Открыть http://127.0.0.1:4000/blog/.

## Структура источника

Источник и каталоги заметок и статей описаны в `content-sources.yml`:

```yaml
repository: ken48/publications
posts: posts
articles: articles
```

Единый обработчик `tools/prepare-content.rb` берёт актуальную основную ветку
репозитория. И заметка, и статья хранятся в файле вида
`YYYY-MM-DD english name.md`. Дата публикации берётся из части имени до
первого пробела. Заголовок берётся из первого заголовка первого уровня в
формате `# Заголовок`; дата в этой строке больше не указывается. Сам заголовок
при публикации удаляется из тела, потому что тема выводит его отдельно.

Полное имя без расширения становится адресом: последовательности пробелов и
дефисов заменяются одним дефисом, а заглавные буквы приводятся к нижнему
регистру:

```text
2026-09-12 Digital Minimalism.md
→ /posts/2026-09-12-digital-minimalism/
→ /articles/2026-09-12-digital-minimalism/
```

В `posts/` обрабатываются все корневые Markdown-файлы. В каждом подкаталоге
`articles/` должен находиться ровно один Markdown-файл с датированным именем.
`README.md`, `lead.md` и другие материалы автоматически не публикуются.
Локальные ссылки на опубликованные `.md`-файлы преобразуются в адреса блога;
query-параметры и якоря сохраняются. Внешние ссылки и ссылки-якоря остаются
прежними. HTML-картинки и обычные Markdown-картинки с относительными путями
копируются в сайт.

Сгенерированные `site/_posts/` и `site/articles/` не нужно добавлять в Git.
Если источник недоступен или картинка отсутствует, сборка завершается
ошибкой; опубликованная версия сайта остаётся прежней.

Изменение репозитория публикаций само по себе не запускает сборку блога.
Чтобы обновить статьи, откройте Actions → Build and Deploy → Run workflow
в репозитории блога. Любой push в `main` блога также обновит все статьи.

Статьи и заметки после подготовки являются обычными постами Jekyll. Поэтому
они одинаково попадают в главную ленту, архив и страницы тегов, сортируются
по дате и получают время чтения и оглавление. Адрес статьи определяется именем её исходного Markdown-файла.
